# Конспект по нотации IDEF0

## Назначение IDEF0
Функциональное моделирование: отвечает на вопрос «что делает система?», а не «как?». Каждая функция описывается через входы (Input), управление (Control), выходы (Output), механизмы (Mechanism) – ICOM.

## Таблица типов дуг ICOM

| Тип | Сторона блока | Вопрос | Пример |
|-----|---------------|--------|--------|
| Input (I) | Слева | «Что перерабатывается?» | Заявка клиента |
| Control (C) | Сверху | «По каким правилам?» | Регламент доставки |
| Output (O) | Справа | «Что получается?» | Выполненный заказ |
| Mechanism (M) | Снизу | «Кем / с помощью чего?» | Диспетчер, 1С |

## Правила построения моделей IDEF0 (7 правил)
1. Имя блока – глагол или глагольная группа.
2. Каждая дуга обязательно подписана (существительное).
3. Не более 6 блоков на одной диаграмме (лучше 3–5).
4. Нумерация узлов строгая: A-0 → A0 → A1, A2 → A11, A12 и т.д.
5. Граничные дуги A-0 должны отражаться на A0 (согласованность).
6. Механизмы должны быть конкретными (не «персонал», а «менеджер по продажам»).
7. Выход каждого блока должен куда-то вести (другой блок или граница).

## Сравнение BPMN vs IDEF0

| Критерий | BPMN | IDEF0 |
|----------|------|-------|
| Фокус | Процесс (поток работ) | Функции и данные |
| Время | Показано явно (последовательность) | Не показано |
| Участники | Дорожки, пулы | Только механизмы |
| Именование | Глаголы | Глаголы (блоки), существительные (дуги) |
| Типичное применение | Регламенты, исполняемые процессы | Системный анализ, верхнеуровневое описание |
